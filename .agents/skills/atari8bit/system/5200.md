# Atari 5200 SuperSystem

> **When to load:** The task involves Atari 5200 porting, memory maps,
> controller input, cartridge layout, or code that assumes XL/XE register
> addresses.
> **Do not use for:** Ordinary Atari 400/800/XL/XE programs unless the user
> explicitly targets the 5200.

## 1. Differences From Atari 8-Bit Computers

The 5200 shares the same basic 6502/ANTIC/GTIA/POKEY family, but software is not binary-compatible with Atari computer programs. The 5200 has no PIA, no CIO device environment like the computer line, relocated GTIA and POKEY addresses, and a smaller console ROM.

| Area | Atari 400/800/XL/XE | Atari 5200 |
|---|---|---|
| RAM | Commonly 16K-64K plus expansions | 16K at `$0000-$3FFF` |
| Cartridge | 8K windows at `$8000-$9FFF` and/or `$A000-$BFFF`, plus `CCTL` at `$D500-$D5FF` | Up to 32K cartridge area at `$4000-$BFFF`; no Atari-computer `CCTL` page |
| GTIA | `$D000-$D0FF` | `$C000-$C0FF` (mirrored within `$C000-$CFFF`) |
| ANTIC | `$D400-$D4FF` | `$D400-$D4FF` |
| POKEY | `$D200-$D2FF` | `$E800-$E8FF` (mirrored within `$E800-$EFFF`) |
| PIA | Present on computers | Not present |
| OS ROM | Larger computer OS ROM with CIO/SIO/editor services | 2K console ROM at `$F800-$FFFF` |
| Controllers | Digital joysticks / paddles / console keys | Analog stick, keypad, Start/Pause/Reset, dual fire buttons |

## 2. Memory Map

| Range | 5200 use |
|---|---|
| `$0000-$3FFF` | 16K RAM |
| `$4000-$BFFF` | Cartridge area |
| `$C000-$C0FF` | GTIA (mirrored within `$C000-$CFFF`) |
| `$D400-$D4FF` | ANTIC |
| `$E800-$E8FF` | POKEY (mirrored within `$E800-$EFFF`) |
| `$F800-$FFFF` | 2K console ROM |

ANTIC display programming is broadly familiar, but computer-line code that writes GTIA or POKEY through `$D0xx` / `$D2xx` must be retargeted. There is no `PORTA/PORTB` banking logic on the 5200.

## 3. Controllers

The standard controller has an analog stick, a numeric keypad (`0-9`, `*`, `#`), Start/Pause/Reset buttons, and two fire buttons. Early consoles expose four controller ports; later revisions expose two.

### Analog stick

The analog stick uses POKEY `POT` inputs.

- Horizontal and vertical axes are read through the `POTx` registers.
- The controller does not self-center accurately; games usually calibrate or apply a software dead zone.
- Software written for digital 8-bit joysticks must be rewritten around thresholds, calibration, or both.

### Keypad and buttons

The keypad is multiplexed through POKEY's keyboard-scan logic rather than through a PIA.

Practical rules:

- Use `CONSOL` to select which controller keypad is being scanned.
- Read keypad results through `KBCODE` / keyboard-scan state, not through computer-line keyboard assumptions.
- Bottom fire buttons appear through `TRIG0-TRIG3`.
- The second/top fire button is tied into the keypad/keyboard-scan circuitry, so code that bypasses the ROM often has to handle it like another scanned button rather than like a second `TRIG` input.

## 4. Porting Rules

- Replace computer GTIA `$D0xx` addresses with 5200 `$C0xx` addresses.
- Replace computer POKEY `$D2xx` addresses with 5200 `$E8xx` addresses.
- Remove PIA/PORTB banking logic; the 5200 has no PIA and no XL/XE extended-memory window.
- Do not depend on CIO keyboard/editor services from the computer OS.
- Rework input around analog thresholds or calibration, keypad scanning, and 5200 trigger behavior.
- Cartridge code can assume a contiguous cartridge region at `$4000-$BFFF`; do not use Atari-computer `CCTL` bank-switch assumptions.
