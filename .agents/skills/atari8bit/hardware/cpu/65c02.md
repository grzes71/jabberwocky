# 65C02

## 1.3  65C02 (CMOS)

New stable instructions vs NMOS:

```
BRA rel   — unconditional branch (2 bytes, 3 cycles, +1 if page crossed)
STZ  $64+ — store zero to abs/abs,X/zp/zp,X
TRB  $14+ — test+reset bits; TSB $04+ — test+set bits
BIT zp    — new zero-page form
BIT abs,X — new absolute form
BIT #imm  — immediate form; updates Z only, leaves N/V unchanged
PHY/PLY $5A/$7A — push/pull Y
PHX/PLX $DA/$FA — push/pull X
WAI $CB — wait for IRQ
STP $DB — stop clock
```

Removed: all 6502 undocumented opcodes have NOP or reassigned replacements.

Decimal mode: N and Z reflect the corrected BCD result; V is also updated from
the corrected result on the 65C02. ADC/SBC take +1 cycle in decimal mode. The
D flag is cleared on reset and on interrupt entry, unlike the NMOS 6502.

### CPU family detection without undocumented opcodes

The NMOS 6502 and CMOS-family parts differ in decimal-mode flag behavior. In
BCD, `$99 + $01` produces zero; the 65C02/65C816 set Z from the corrected
decimal result, while the NMOS 6502 leaves Z as if the binary add happened.

```asm
; Z=1 on 65C02/65C816, Z=0 on NMOS 6502
detect_cmos
        lda   #$99
        clc
        sed
        adc   #$01
        cld
        ; BEQ => corrected decimal result reached zero (CMOS family)
```

Use a documented 65C816-only opcode such as `XCE`, `REP`, or `SEP` to
distinguish a 65C816 from a 65C02. Do not rely on undocumented NMOS opcodes for
family detection.
