# 65816 Math

## 10.4 65816-Specific Math

### LONGA / LONGI / REP / SEP

```asm
        rep   #$20    ; A = 16-bit
        sep   #$20    ; A = 8-bit
        rep   #$10    ; X/Y = 16-bit
        sep   #$10    ; X/Y = 8-bit
```

In MADS, switch the assembler to 65816 mode with `opt c+` first — without it,
65816 mnemonics are treated as macro names and 16-bit forms are rejected
(`.longa on` also fails with *Illegal addressing mode (CPU 6502)*).
Two ways to declare the register widths, and they differ:

- `.A8` / `.A16` / `.I8` / `.I16` emit the mode-switch instruction as well
  (`SEP #$20` = `E2 20`, `REP #$20` = `C2 20`, `REP #$10` = `C2 10`).
- `.LONGA ON|OFF` / `.LONGI ON|OFF` only tell the assembler what width to assume
  — no code is emitted (verified: `.longa on` + `lda #$1234` = `A9 34 12` with no
  preceding `C2 20`); use them when the mode was already set by `SEP`/`REP` or by
  a previous routine.

Verified with MADS 2.1.7: with `opt c+`, `rep #$20` emits `E2 20`, `sep #$20`
emits `C2 20`, `lda #$1234` under `.a8` emits `A9 34`, and `ldx #$5678` under
`.i16` emits `A2 78 56`.

The practical win for math code is fewer explicit carry chains: 16-bit
`ADC`/`SBC`, `INC/DEC`, and index arithmetic can replace two-byte 6502
sequences. `XBA` is also useful for byte shuffles.

### `BIT #imm` is not a carry trick

On 65C02/65816, `BIT #imm` is an immediate test that updates Z from `A & imm`.
It does **not** preload carry, and unlike memory `BIT` it does not copy operand
bits 7/6 into N/V.

### No generic on-chip multiplier/divider

A bare 65816 does **not** provide a built-in hardware multiply/divide unit.
Addresses such as `$4202/$4203` are platform-specific peripherals (for example
the SNES CPU register block), not part of the generic 65816 programming model.
On Atari 65C816/Rapidus-style systems, multiplication and division are still
normally done in software or with lookup tables.
