# Domain: Python Tooling, Build Pipeline & GUI Editors

## 1. Architecture & Paradigms
- **Purpose:** Python in `scripts/` compiles SSOT data into `gen/*.asm` / `*.bin`; the `*_studio/` packages are PySide6 editors that write the SSOT; `tests/` verifies both.
- **Data models:** use `pydantic` v2 (preferred) or `dataclasses` for YAML/JSON parsing and intermediate models. Start modules with `from __future__ import annotations` and annotate everything.
- **Structure-of-Arrays (SoA):** when emitting engine tables, ALWAYS output parallel SoA tables (`*_lo` / `*_hi`, one array per attribute) — never array-of-structures — so 6502 code can index with `LDA table,X`.
- **Generated output:** each `gen/` file starts with a header such as `; AUTO-GENERATED by scripts/<tool>.py — do not edit` and must be deterministic (stable ordering, no timestamps) so diffs stay meaningful.

## 2. Style & Quality
- **Type hinting:** complete hints on every function and method; `pathlib.Path` instead of string paths.
- **Dependencies:** keep `requirements.txt` minimal and pinned (pydantic, PyYAML, PySide6, pytest, py65, Pillow, numpy, atari-image-converter). Justify any new dependency.
- **CLI design:** `argparse` only (this project does not use `click`), explicit input/output flags, `0` / non-zero exit codes, errors on `stderr` so `make` breaks immediately.
- **Makefile wiring:** a tool is only "integrated" once it has an explicit file-target rule in the `Makefile` (sources + script → generated file) and is reachable from `assets`, `data` or `check_memory`.

## 3. GUI Editors (`labirynt_studio/`, `object_studio/`, `sprite_studio/`)
- Editors read and write the SSOT directly: `world/project.yaml`, `world/objects.yaml`, `sprites/jabberwocky.json`. Never introduce a second, parallel data format.
- Keep model / validation / IO logic outside widgets so it stays unit-testable without a window.
- After changing anything that affects compiled data, run `make all` and `make test`.

## 4. Testing
- Use `py65` (`from py65.devices.mpu6502 import MPU`) to load `jabberwocky.xex`, execute 6502 routines and compare RAM/state against the Python model — see [05-tests.md](05-tests.md) for the harness contract.
- GUI tests create their own `QApplication`; `pytest-qt` is **not** a dependency of this project.
